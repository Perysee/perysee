# Contributing to Perysee

Thanks for helping. Here is how it works.

## Before you start

- **Bugs**: open an issue with your Perysee version, PHP version, MariaDB version
  and hosting type (shared, VPS, Docker).
- **Features**: open an issue first. A short discussion avoids a pull request
  that cannot be merged.
- **Security issues**: do not open a public issue. Read [SECURITY.md](SECURITY.md).
- **Modules**: modules live in their own repositories. Start from the
  [module template](https://github.com/Perysee/perysee-module-template).
  The core only accepts changes to the Module API itself.

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Keep one topic per pull request.
3. Add or update tests when you change behavior.
4. Run the test suite and the linter before pushing.
5. Describe what changes and why. Link the related issue.

## Contributor License Agreement

Your first pull request triggers the CLA Assistant bot. Read the
[CLA](CLA.md) and sign it with a comment. It takes one minute.

Why a CLA: the core is AGPL with a Module Exception. Without the CLA, the
project could not keep granting that exception on code you wrote. The CLA also
commits the project to keep your contributions open source.

## License of your contribution

By contributing, your code is distributed under AGPL-3.0-only with the Perysee
Module Exception, like the rest of the core. Add the standard file header from
[LICENSING.md](LICENSING.md) to new files.

## Code of conduct

Everyone taking part follows the [Code of Conduct](CODE_OF_CONDUCT.md).

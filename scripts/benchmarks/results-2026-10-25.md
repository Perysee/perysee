# Laboratoire local — 25 octobre 2026

PHP 8.5.7, MariaDB 11.4.8, Apple M1 ; conteneur SQL 2 vCPU / 1 Gio. Quatre workers du serveur PHP de développement, bouclage local, client `node:http`, poste de développement non isolé. Aucun résultat ne qualifie un mutualisé.

Chaque profil dure environ une minute, à cadence fixée. Payload v1 compatible ancien tracker : pages vues sur 50 chemins, sans session, référent ni UTM. Les fonctionnalités modernes sont couvertes par les tests, mais leur coût ne se déduit pas de cette charge. Le quota d’une IP unique est neutralisé par cache array dans ce laboratoire. Pas de warmup séparé, ni de répétitions statistiques indépendantes.

Laravel reste le collecteur MVP. Les prototypes minimal et PDO ne valident pas le même périmètre de sécurité et ne doivent pas être déployés. Le P95 de Laravel à 10 000/min dépasse la cible de 100 ms dans cette mesure ; cette cible n’est donc pas démontrée pour ce pic. Il faut mesurer Apache/LiteSpeed, quotas réels, contention voisine et payloads enrichis avant de décider d’une extraction.

Deux exécutions cohérentes du client corrigé couvrent les neuf profils : 33 300 confirmations, 33 300 événements durables puis consolidés, sans double comptage. Le JSON contient les tailles et pics mémoire par exécution. Les estimations de stockage concernent la table complète InnoDB, pas une extrapolation à des millions de lignes.

- Exécution de 12200 événements : consolidation 1826.63 ms ; 100 lectures de rapports 30 jours, P95 5.91 ms ; table brute estimée à 2457600 octets. Les rapports ne couvrent qu’un jour effectivement rempli et 50 chemins ; le coût d’un jeu volumineux n’est pas démontré.

- Exécution de 21100 événements : consolidation 3324.28 ms ; 100 lectures de rapports 30 jours, P95 5.83 ms ; table brute estimée à 3981312 octets. Les rapports ne couvrent qu’un jour effectivement rempli et 50 chemins ; le coût d’un jeu volumineux n’est pas démontré.

Le premier client basé sur fetch a échoué nativement. Ses résultats sont exclus de la comparaison ; les 19 330 événements déjà persistés de cet essai ont été consolidés, puis le seul site synthétique a été nettoyé. Les profils ont été répétés avec le client HTTP corrigé, y compris ceux qui avaient déjà réussi.

Reproduction depuis la racine du dépôt applicatif, avec la base dédiée configurée (ne pas lancer les tests MariaDB simultanément) :

```sh
node scripts/benchmarks/run.mjs 60 /tmp/perysee-benchmark.json
```
